## 2. Qué conseguimos con esta fase

- **`tenant_members`, `tenant_configs`, `tenant_invites`, `tenant_audit_events`** creadas y usables (F04.10b): no son tablas SQL nuevas (evitamos tocar el esquema de `records`), sino **kinds nuevos en `records`** (`"tenant-members"`, `"tenant-configs"`, `"tenant-invites"`, `"tenant-audit-events"`). El modelo sigue siendo `records(owner, kind, id, data)`, así que no hace falta migración SQL. Marca `TENANT_MEMBERS_TABLE_V1`.
- **`DatabaseTenantResolver` cableado** (F04.10c): `app.ts` inyecta `DatabaseTenantResolver(db, fallback)` en el kernel si `MULTI_TENANT_SHARED=true`, o `ServiceTenantResolver(tenantService)` si no. **El fallback es `ServiceTenantResolver` en ambos casos**, pero el primario cambia según el modo. Marca `DB_TENANT_RESOLVER_WIRED_V1`.
- **`DatabaseTenantConfigResolver` inyectado** (F04.10d): `app.ts` construye `DatabaseTenantConfigResolver({ query }, envResolver)` si `MULTI_TENANT_SHARED=true`, o `EnvTenantConfigResolver` si no. Marca `DB_TENANT_CONFIG_RESOLVER_WIRED_V1`.
- **`/api/auth/switch-tenant`** (F04.14b): endpoint que valida membership y emite un nuevo JWT con `tenantId` en el payload. Con `/api/auth/me` que ya devuelve `user`, el switch permite al usuario cambiar de tenant activo. Marca `SWITCH_TENANT_ENDPOINT_V1`.
- **`setMembership` con invalidación + evento** (F04.14c): `TenantService.setMembership` emite `TENANT_MEMBERSHIP_CHANGED` al bus (con `eventBus` opcional en el constructor) y llama `invalidateAll()` además de actualizar la caché del owner. Marca `MEMBERSHIP_CACHE_INVALIDATE_V1`.
- **`migrate-tenant-scope.ts` transaccional** (F04.11): el script envuelve la actualización en `db.transaction(...)`. Si alguna fila falla, rollback. Marca `MIGRATE_SCOPE_TX_V1`.
- **`migrate-tenant-membership.ts` verificado** (F04.11b): el script **ya existe** en `scripts/migrate-tenant-membership.ts` y es idempotente (skip si id==default, skip si tenantId vacío, skip si ya existe default). Se verifica con `Test-Path` y se documenta en `-pendientes.md` como "no requiere cambios". Marca `MIGRATE_MEMBERSHIP_VERIFIED_V1`.
- **`admin-tenants.ts` CRUD de memberships** (F04.12): añade `DELETE /api/admin/tenants/:tenantId` que borra el registro `tenant-membership` y `tenant-configs` del tenant, y `PATCH /api/admin/tenants/:tenantId` que cambia `displayName`. Marca `ADMIN_TENANTS_CRUD_V1`.
- **N02/N03 refinos**: `admin-tenants.ts` usa `tenantService.setMembership` (que ahora emite evento) y `invalidateAll`. Ya está casi completo desde Fase 2; aquí se refina para emitir el evento y añadir `switch-tenant`.
- **F04.27 sigue bloqueado** (`backup-tenant.ts` no está en Repomix). Se documenta en `-pendientes.md`.
- **Cero cambios de comportamiento en clone-por-cliente** con `MULTI_TENANT_SHARED != "true"`: `DatabaseTenantResolver` y `DatabaseTenantConfigResolver` no se usan, `/switch-tenant` devuelve 400 si el usuario no tiene memberships múltiples, `setMembership` emite evento (que no rompe), y los scripts de migración no se ejecutan.

### A.12. `scripts/migrate-tenant-membership.ts` — script actual (Repomix holístico, literal, sin cortes, ya idempotente):

```typescript
// MIGRATE_TENANT_MEMBERSHIP_V1
// Unifica todas las filas de tenant-membership a id="default".
// Uso: pnpm exec tsx scripts/migrate-tenant-membership.ts

import { createStore } from "../apps/server/src/db.ts";

async function main() {
  const db = await createStore({
    dataDir: process.env.DATA_DIR ?? ".openmuse",
    databaseUrl: process.env.DATABASE_URL,
  });
  try {
    const rows = await db.list<{ id: string; tenantId: string }>(
      "system",
      "tenant-membership",
      { limit: 10000 },
    );
    let migrated = 0;
    let skipped = 0;
    for (const row of rows) {
      if (row.id === "default") { skipped++; continue; }
      if (!row.tenantId) { skipped++; continue; }
      const existing = await db.get("system", "tenant-membership", "default");
      if (existing) { skipped++; continue; }
      await db.put("system", "tenant-membership", {
        id: "default",
        tenantId: row.tenantId,
        migratedAt: new Date().toISOString(),
        migratedFrom: row.id,
      });
      await db.remove("system", "tenant-membership", row.id);
      migrated++;
    }
    console.log(`OK: ${migrated} migradas, ${skipped} saltadas`);
  } finally {
    await db.close();
  }
}

void main();
```

**Confirma que es idempotente. F04.11b no requiere cambios.**

```typescript
  private inTransaction = false;
  async transaction<T>(fn: (tx: Store) => Promise<T>): Promise<T> {
    if (this.inTransaction) return fn(this);
    const raw = this.db as { query: (sql: string, params?: unknown[]) => Promise<unknown> };
    await raw.query("BEGIN");
    this.inTransaction = true;
    try {
      const result = await fn(this);
      await raw.query("COMMIT");
      return result;
    } catch (error) {
      try { await raw.query("ROLLBACK"); } catch { /* rollback best-effort */ }
      throw error;
    } finally {
      this.inTransaction = false;
    }
  }
```
