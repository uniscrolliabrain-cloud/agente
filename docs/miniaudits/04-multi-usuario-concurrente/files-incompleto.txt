# Documento maestro de archivos por campaña

## Propósito y contrato de uso

Este documento existe para que **una IA futura pueda aplicar cualquier campaña de la Campaña 2 (F0–F7) sin agotar el contexto de chat**. La regla es:

- **Un documento por campaña, autocontenido.**
- **Cada documento lista: ficheros que crea, ficheros que modifica, ficheros que cablea (wire), ficheros que solo lee, y ficheros que NO toca.**
- **Cada entrada incluye: ruta, operación (CREATE/MODIFY/WIRE/READ), motivo, marca de idempotencia, dependencias y precondición.**
- **El tamaño de cada documento debe caber en ~50 % del contexto del chat** (≈1,1 MB de texto). Por eso las fases grandes (F2, F3) se parten en subdocumentos: `F2-core`, `F2-routes`, `F3-core`, `F3-adapters`. Cada subdocumento es aplicable por separado.
- **La IA ejecutora no necesita leer el repositorio entero.** Cada documento le dice exactamente qué ficheros inspeccionar con `Select-String`, qué ficheros leer completos y qué ficheros no toca.

# 1. Convenciones del documento

| Símbolo | Significado |
|---|---|
| **CREATE** | El fichero no existe en el árbol; el patchset lo crea. |
| **MODIFY** | El fichero existe; el patchset lo modifica con `$old`/`$new` y `Assert-MatchCount`. |
| **WIRE** | El fichero existe; el patchset añade una llamada/registro (p. ej. `app.route(...)`) sin reescribir el cuerpo. |
| **READ** | El patchset solo lee el fichero con `Select-String` o `Get-Content` para verificar anclas. No lo modifica. |
| **NO TOUCH** | Prohibido modificarlo en esta campaña; si aparece un cambio necesario, se documenta como deuda. |

**Reglas de idempotencia:**
- Cada MODIFY/CREATE lleva una marca única `AMBITO_FICHERO_V<n>` en un comentario del código.
- Si la marca ya existe y el checksum coincide → `SKIP`.
- Si la marca existe y el checksum no coincide → `AVISO` y abortar.
- Si la marca no existe → aplicar.

**Reglas de tamaño:**
- Un subdocumento (`F2-core`, `F2-routes`, `F3-core`, `F3-adapters`) no debe superar 1,2 MB de texto. Si lo supera, se parte en `-part1` / `-part2`.
- Una IA ejecutora debe poder leer el documento completo + los ficheros READ + ejecutar los patchsets sin superar el 50 % del contexto. Si no cabe, se le pasa solo el subdocumento.

## 5. Reglas para futuras IA

Estas son las reglas que cualquier IA debe seguir al aplicar una fase del maestro. Están derivadas del protocolo TypeScript v2 y del protocolo de campaña.

**R1 — La fuente de verdad es el disco.** No el Repomix, no el maestro, no la memoria del chat. Si un fichero ha sido tocado por una fase anterior, el Repomix original es referencia histórica. Se lee con `Get-Content -Raw`.

**R2 — Un patchset = un fichero + un propósito.** No se agrupan cambios independientes. No se refactoriza código ajeno al objetivo.

**R3 — Ancla literal, no aproximada.** El `$old` se copia del fichero real, con indentación y line ending exactos. Si el ancla no coincide exactamente 1×, se aborta. No se improvisa.

**R4 — Función envolvente, `throw` en comprobaciones.** Todo patchset va dentro de `function Invoke-F<X>_<Y> { ... }` y se llama. Las comprobaciones usan `throw`, no `return`. El `return` solo se usa para el `SKIP` por idempotencia.

**R5 — Escritura atómica.** `[System.Text.UTF8Encoding]::new($false)` + `[System.IO.File]::WriteAllText`. Backup en `.tmp/patchset-backups/` antes de escribir.

**R6 — Verificación post en disco.** Tras escribir, se relee el fichero, se cuenta la marca, se verifica que el `$old` ya no está y que el `$new` está.

**R7 — `git diff` es la verificación final.** Si el diff no es exactamente el cambio esperado, se revierte con `Copy-Item $backup $file -Force` y se diagnostica.

**R8 — Typecheck y test son obligatorios.** Se corre `pnpm --filter "@openmuse/server" exec tsc --noEmit` y `pnpm test`. Se distinguen errores nuevos de preexistentes. Si hay error nuevo, se revierte el fix.

**R9 — No se declara `PASS` sin ejecutar.** La IA entrega el bloque. El humano lo ejecuta y pega el output. La IA no declara `PASS` si no ha visto el output.

**R10 — Los misses van a `missed/_multiusuario_pendientes.md`.** La IA no lo escribe. El humano lo revisa.

**R11 — Los tests de la campaña van a `tests/campaign-2/`.** No se congelan. Los tests ajenos a la campaña siguen congelados hasta F7.

**R12 — Si falta un fichero, se pide.** No se inventa. El maestro declara `Select-String` como precondición cuando el fichero no está pegado.
