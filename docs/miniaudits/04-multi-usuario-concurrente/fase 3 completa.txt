**Campaña:** 2 — Multiusuario
**Fase:** 3 — Delegación controlada

**Base:** F1 (identidad) + F2 (acceso) cerradas.
**Alcance:** 26 patchsets (14 CREATE + 12 MODIFY) + 8 tests de aceptación.
**Protocolo:** PowerShell v2.1 + protocolo TypeScript v2 (throw, `Assert-MatchCount`, backup, `WriteAllText` UTF-8 sin BOM, typecheck por tanda).

---

## 1. Objetivo

Unificar `AgentTask`, `Goal`, `Monitor`, `ActionProposal` y `SOP` bajo una interfaz de lectura `Assignment` sin duplicar persistencia. Separar `assignedBy` (delegante) de `assignedTo` (ejecutor) y de `owner` (ámbito de almacenamiento). Construir `Flow` desde `AgentPersona.reportsTo`/`peers`, no desde `AgentRole`. Garantizar que el agente ejecutor **no escala permisos** por encima del asignador (T13). Todo con autorización por recurso real, no solo por `kind`.

## 6. Contratos clave

### `Assignment` (F3.1)

- `id = ${kind}:${recordId}` (B-N1).
- `tenantId`, `kind` (`task|goal|monitor|approval|sop`).
- `assignedTo: string | null` (bandeja de pendientes), `assignedBy: string | null`.
- `status: AssignmentStatus` (unión real de los 5 kinds), `nativeStatus: string` (B-N2).
- `plan?`, `evidence[]`, `outcome?` (reusa `outcomeStatusSchema` de `outcome.ts`).
- `metadata?: Record<string, unknown>` declarado y validado (2.2).
- **No se persiste**. Se computa on-the-fly desde el record con el adapter.

### `Flow` (F3.2)

- `reportsTo?: FlowRelation`, `peers: FlowRelation[]`.
- `FlowRelation = { actorId, personaId, kind, role, tenantId }`.
- **No persistido**. Se computa en `PersonaRegistry.register`.
- **`assigners`/`approvers`/`reviewers` NO en `Flow`**, se resuelven desde `Policy`.
- `personaId` se resuelve contra `Actor` real del tenant; rechaza cruces (3).

### `AssignmentService` (F3.6)

- `assign(ctx: PolicyContext, kind, recordId, assignedTo: string | null, assignedBy: string): Promise<Assignment>`.
- `assignedBy` debe ser `ctx.actor.id` (1.2).
- `P_efectivos = P_asignador ∩ P_ejecutor ∩ P_tarea ∩ P_tenant` (1.1).
- `accept`, `reject`, `approve`, `escalate`, `reassign`, `complete`.
- `complete` de task mapea a `PolicyAction.execute` (B-N5).
- Emite eventos al bus. Llama a `withWrite`.
- **No crea record `Assignment` paralelo**.

### `assignmentsRoutes` (F3.7)

8 handlers. Cada uno:
1. Carga el record original.
2. Verifica tenant.
3. Autoriza la transición con PDP.
4. Solo entonces escribe.
5. No acepta `tenantId`/`assignedBy`/`status`/`kind` del body para saltarse restricciones (1.3).

### Adapters (F3.5–F3.5e)

- `toAssignment(record)` → vista normalizada.
- `applyAssignment(record, changes)` → aplica solo campos autorizados; los específicos se conservan.
- `applyStatus(record, status)` → mapea canónico a nativo.
- `toCanonicalStatus(native)` / `toNativeStatus(canonical)` por kind.
- Sin `z.any()`. Sin pérdida de datos.
