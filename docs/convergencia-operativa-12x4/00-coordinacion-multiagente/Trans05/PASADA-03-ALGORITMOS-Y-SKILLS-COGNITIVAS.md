## Design P01–P12
P01 freeze baseline and measure calls, bytes, queue lag, provider cost; identify existing slow schema consumers before versioned migration.
P02 anchor proposals carry exact evidence, operation add/refine/dispute/supersede, expected head revision. No model authority. P03 graph retrieval bounded by thread, exact refs and edge/node limits; graph distance is not truth.
P04 catalog v1 (candidate IDs, trigger, output, stop):
- first_principles: explicit axiom or contradiction; premises and dependencies; stop when all claims anchored or unknown.
- perspectives: complex decision; alternatives from distinct stakeholder/technical/time viewpoints; stop at 3 materially distinct perspectives.
- abstraction: recurring examples; generalized pattern with exceptions; stop if no evidence across examples.
- concretization: vague concept; operational example and acceptance criterion; stop at one testable example.
- contradiction: incompatible propositions in same scope/time; paired refs and conflict candidate; stop without automatic resolution.
- drift: goal/answer mismatch; missing anchor refs; stop if no material mismatch.
- causal: causal claim; assumptions, alternatives and evidence gaps; no causal certainty from correlation.
- counterfactual: decision uncertainty; explicit changed assumption and consequence hypothesis; stop at bounded alternatives.
- synthesis: checkpoint or topic transition; source-backed deltas, not recursive summary.
- strategy: goal and constraints; ordered conceptual options, no operational dispatch.
- meta_review: evaluate evidence coverage, unresolved questions and scope; no private reasoning persistence.
- feedback: correction or evaluation; candidate revision, no policy self-modification.
Composite six-frame strategy/diagnosis/simulation/feedback/redesign/execution-documentary: one bounded inference where feasible, structured outputs not six compulsory calls. Execution here means producing informational artifact, never business action.
P05 selector pure candidate (new engine/cognition/v2/longitudinal/selector.ts proposed):
```ts
type Pole="explore"|"apply"|"generate"|"verify"|"expand"|"protect";
type Skill={id:string;version:string;triggers:readonly string[];weights:Partial<Record<Pole,number>>;cost:number};
type Signal={triggers:ReadonlySet<string>;poles:Record<Pole,number|null>;remaining:number};
function selectSkills(catalog:readonly Skill[],s:Signal){
 return catalog.filter(k=>k.cost>0&&k.cost<=s.remaining&&k.triggers.some(t=>s.triggers.has(t)))
 .map(k=>{let sum=0,known=0;for(const p of Object.keys(k.weights) as Pole[]){const v=s.poles[p],w=k.weights[p]??0;if(v!==null){sum+=v*w;known+=Math.abs(w)}}return {k,score:known?sum/known:0}})
 .sort((a,b)=>b.score-a.score||a.k.id.localeCompare(b.k.id)).slice(0,1).map(x=>x.k);
}
```
