# W11 — Índices de thoughts separados de los turnos

Base `964d666`. `StoreTurnStore.append` escribía el índice `{id,turnId,thoughtId,tenantId}` con el mismo tipo de almacenamiento que los turnos (`cognitive-turns`). `listTurns`, `listTurnsForOwner` y `listOpenTurnsForThread` parseaban después esos índices como turnos y lanzaban ZodError en cuanto un turno tenía thoughts. El defecto estaba documentado en `REPORT-W11-BRIDGES.md` y quedaba sin corregir.

Cambios: los índices nuevos usan `cognitive-turn-thought-indexes`; los lectores de turnos saltan únicamente filas que cumplen exactamente la forma del índice histórico dentro del mismo tenant, conservan el orden y siguen fallando cerrado ante cualquier registro malformado distinto. El sobre-fetch está acotado por el mismo tope duro de 200 turnos y 1000 filas que ya aplicaba el store. Los índices históricos **no se borran ni se migran**: siguen legibles para recuperación y no se devuelven como turnos. `thoughtsOf` sigue leyendo el turno real y la lista `thoughtIds`, sin depender de los índices.

Prueba nueva `tests/kernel-turn-index.test.ts` con el store persistente PGlite: escribe un turno con thought, inserta a mano un índice con el formato antiguo bajo `cognitive-turns` y verifica que `listTurns`, `listOpenTurnsForThread` y `listTurnsForOwner` devuelven sólo el turno real y que la fila histórica sigue existiendo. Foco: `tests/kernel-turn-index.test.ts tests/kernel.test.ts tests/kernel-persona-isolation.test.ts tests/kernel-coherence.test.ts` → 18/18 PASS, 0 omitidas. `tsc --noEmit`: PASS. Suite V2 completa en la misma rama: 69/69 PASS con PostgreSQL sintético.

Límites: la corrección no reescribe datos históricos ni cambia la paginación más allá del sobre-fetch acotado; un tenant con más de 1000 filas de almacenamiento de turnos e índices históricos mezclados puede seguir viendo menos turnos de los solicitados, y eso no se ha medido a escala. No se ha probado sobre una base de producción. No se ejecutó el gate general para este patchset; C15 sigue NO_GO y no se ha desplegado nada.
